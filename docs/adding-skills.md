# 新增 Skill 指南

## 目录与命名

每个 Skill 直接放在仓库根目录，使用 `haoyuan-` 前缀和小写短横线命名，例如 `haoyuan-example`。下面仅为结构示例，目前仓库中没有该 Skill。

```text
haoyuan-example/
├── SKILL.md          # AI 读取的入口：触发条件、步骤及边界
├── README.md         # 人阅读的说明：用途、安装、配置与示例
├── scripts/          # 可选：该 Skill 专用的脚本
├── references/       # 可选：按需读取的参考资料
└── assets/           # 可选：模板、示例与素材
```

只创建实际需要的子目录。仓库根目录的 `scripts/`、`assets/` 用于多个 Skills 共用的资源；单个 Skill 所需内容尽量保存在自己的目录内，方便独立安装和维护。

## SKILL.md 起点

下面的内容需要替换为真实能力，不应原样作为可用 Skill 发布。

```markdown
---
name: haoyuan-example
description: 说明这个 Skill 做什么，以及用户在什么场景下应使用它。
---

# 能力名称

## 适用场景

描述解决的问题、所需输入与预期输出。

## 操作步骤

1. 确认输入和必要条件。
2. 按实际流程执行，说明需要读取的参考资料或调用的脚本。
3. 核对结果并交付。

## 边界与异常处理

说明不支持的情况、失败时如何处理，以及对外写入等动作所需的用户意图。
```

## 配套 README

每个 Skill 的 README 应说明用途、支持的 AI 工具和操作系统、依赖、安装位置、配置方式、调用示例、预期结果与已知限制。有外部依赖时，在 Skill 内维护相应依赖声明；JavaScript/TypeScript 使用 Bun，Python 使用 uv，第三方组件遵循上游约定。

## 加入仓库

1. 整理自己的实现与必要资料，替换个人绝对路径，使用可公开的示例数据。
2. 若包含第三方内容，保留署名与许可证，并更新根目录 `THIRD_PARTY_NOTICES.md`；不要仅因源码可见就假定可以再发布。
3. 按说明运行一次有代表性的实际任务，记录验证环境、日期、结果及尚未验证的部分。
4. 更新根目录 README 的 Skills 索引，链接至该 Skill 的 README。

账号登录态、API Key、聊天原文和私人业务资料保存在仓库外。需要配置示例时提供无真实凭据的 `.env.example`。
