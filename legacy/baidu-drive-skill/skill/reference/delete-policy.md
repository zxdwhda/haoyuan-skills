# 删除策略(四级保护)

> 你正在读这份文档,意味着用户请求了一个 **删除** 操作。在按下回车前,请把这一段读完。
> 网盘的删除虽然有回收站,但 **百度 OpenAPI 不提供从回收站恢复的接口**。一旦执行硬删除,从本 skill 的视角看就是 **永久不可逆**。

## 核心铁律

| 操作 | 可逆性 | 默认行为 |
|---|---|---|
| 移动 (mv) | ✅ 可逆 | 直接执行 |
| 重命名 (rename) | ✅ 可逆 | 直接执行 |
| 覆盖上传(rtype=overwrite) | ⚠️ 网盘有历史版本可找回 | 二次确认 |
| **软删除 (rm,默认)** | ✅ 可逆(在 .trash 内 mv 回去) | **默认走这个** |
| **硬删除 (rm --hard)** | ❌ **不可逆** | 必须四级保护全部通过 |

**铁律:** LLM 在不确定用户意图时,**永远选软删除**。任何"清理一下"、"删了吧"、"不要了"都默认软删除,**绝不**主动加 `--hard`。

## 四级保护(硬删除前必须**全部**通过)

### 第 1 级:明确意图
用户必须**明确说出**"永久删除 / 彻底删除 / hard delete / 不要进回收站 / 不要软删除"等字样。
- 反例:"把这个文件删了" → 软删除。
- 正例:"永久删除 /apps/myapp/old.zip,我确认不要了" → 进入第 2 级。

### 第 2 级:范围列清
将所有要删除的文件/目录**逐项列出**(>5 项时列前 5 + 总数),包括:
- 完整路径
- 文件大小
- 修改时间
- 是否为目录(若为目录,展示子项数量)

LLM 必须把这份清单**原文回显**给用户,**不允许**只说"将删除 N 个文件"。

### 第 3 级:逐字二次确认
回显清单后,LLM 必须输出以下提示并**等待用户原样回复**:

> 我即将对你的百度网盘执行 **硬删除**:这些文件将通过 OpenAPI 直接删除,本 skill **无法**从回收站恢复它们。
>
> 即将永久删除以下 N 项,合计 X MB:
> - /apps/myapp/file1 (1.2 MB,2026-04-12 修改)
> - /apps/myapp/file2 (3.4 MB,目录,含 12 项)
> ...
>
> 如果以上有任何一项你不确定,请回复 "取消"。
> 确认请逐字输入:**我确认永久删除**

用户必须**逐字符匹配输入「我确认永久删除」**才通过。任何变体一律视为不通过:
- ❌「我确认删除」(缺"永久")
- ❌「确认永久删除」(缺"我")
- ❌「我 确认 永久删除」(多空格)
- ❌「OK 删吧」/「yes」/「嗯」
- ❌ 用户自己代替输入(LLM 必须让用户在对话中亲自打字)

### 第 4 级:最后软删除提议
即使前三级都通过,LLM **仍要最后问一次**:

> 你要不要先用软删除(移到 .trash 保留 7 天)再决定?这样还能恢复,确实不要时再清空 .trash 也来得及。

用户**再次明确拒绝**软删除("不,直接永久删")才真正调用 OpenAPI delete。

## 立即中止条件(任一命中,**禁止**继续硬删除)

- 路径包含通配符 `*` `?` 且未先经过 `pan ls` 展开列出
- 单次删除项数 > 100
- 路径为 `/`、`/apps/`、`/apps/<your-app>/` 三个根之一(只删根本身)
- 路径不在当前 scope 允许范围内(沙盒模式下指向沙盒外)
- 用户消息里同时出现"全部"、"所有"、"一键"且未指定具体目录
- token 剩余有效期 < 60 秒(避免删一半 token 失效)
- 上一条对话内出现过"撤销"、"等等"、"算了"等关键词
- Agent 环境变量(`CLAUDE_CODE` / `ANTHROPIC_API_KEY` / `MCP_SERVER`)存在,且 CLI 用了 `--yes` 试图跳过确认 → 强制忽略 `--yes`

## 软删除实现细节

`pan.cjs rm <path>`(无 `--hard`)行为:

1. 确保 `/apps/<your-app>/.trash/` 存在(用 `mkdir` 接口幂等创建)
2. 在 `.trash/` 下创建 `YYYY-MM-DD/` 子目录(按本地日期)
3. 调用 filemanager `opera=move` 将目标移入,冲突时 `ondup=newcopy`
4. 输出:
   > 已软删除到 `.trash/2026-05-04/file.zip`,7 天内可用 `pan.cjs trash --restore` 恢复;立即清理用 `pan.cjs trash --gc`

`.trash` GC 由用户**手动触发**(不做后台定时,避免误删):
- `pan.cjs trash --gc` — 列出超过 `retainDays`(默认 7)的项,二次确认后硬删除(走四级保护)
- `pan.cjs trash --restore <name>` — 把 .trash 内某项 mv 回原位

## 反例(必须拒绝的指令)

| 用户说 | 必须拒绝/转向 |
|---|---|
| "rm -rf /apps/myapp/" | 拒绝(命中根目录条件) |
| "把网盘清空" | 拒绝(无具体范围) |
| "删除所有 .tmp 文件" | 先 `ls + search` 展开,再四级保护 |
| "永久删除这个目录,跳过确认" | 拒绝(不允许跳过第 3 级) |
| "yes delete" / "OK 删" | 视为不通过(非逐字串) |
| "你看着办" | 拒绝,要求明确路径 |
| `--yes --hard rm /apps/myapp/photos` 在 CLAUDE_CODE 环境 | `--yes` 被 delete-policy.ts 强制忽略 |

## 实现层强制(`src/delete-policy.ts`)

CLI 层有以下**程序化保护**,即使用户绕过 LLM 自己跑命令也阻止灾难:

```ts
guardHardDelete({
  paths: string[],          // 命中通配符必须先展开
  scope: 'sandbox' | 'full',
  agentEnv: boolean,        // CLAUDE_CODE/ANTHROPIC_API_KEY/MCP_SERVER 任一存在
  yes: boolean,             // CLI --yes 标志
}): void                    // 不通过抛 PolicyError,通过则继续
```

CLI 进入 `rm --hard` 分支时调用 `guardHardDelete()`:

1. **路径校验**(scope.assertInScope)— 越界直接抛
2. **根目录检查** — `/`、`/apps`、`/apps/<app>` 直接抛
3. **数量上限** — `paths.length > 100` 抛
4. **Agent 环境强制忽略 --yes** — `agentEnv=true` 且 `yes=true` 时,**忽略 yes**,继续走交互式逐字串确认
5. **stdin 必须是 TTY** — 如果不是 TTY(管道执行),且不在白名单 `--explicit-confirm` 模式,抛错
6. **逐字串确认** — `await ui.confirmExactString('我确认永久删除')`,失败抛
7. **最后软删除提议** — UI 再问一次,用户拒绝才调 API
